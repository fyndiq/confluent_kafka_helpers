# Migration Guide for v0.6

Migrating from `0.5` (`v0.5.2`) to the latest `0.6.x` (`v0.6.1`).

## Required changes

- **`confluent-kafka==0.11.4`** (was `==0.11.0`). Install from PyPI; the old dependency-link pin is gone.
- **Avro stack**: `fastavro==0.18.0` (ujson extra removed) and `avro-python3==1.8.2`. Stats parsing now uses stdlib `json`.
- **Producer defaults**: `queue.buffering.max.ms` is `100` (was `0`), `max.in.flight` is `1`. Override if you still need the old latency / in-flight behavior.
- **`fetch.message.max.bytes=10500` default removed** on consumer and loader — large messages work again without an override.
- **Loader `key_filter` sees serialized keys**: `load` passes the Avro-encoded key into the filter, and the lazy consumer has not decoded `message.key()` yet. A custom filter that compared Python keys must encode first (the default `==` filter still works).

### Migration steps

1. Upgrade the Kafka client and Avro packages to the 0.6 pins and drop `fastavro[ujson]`.
2. If you depended on immediate produce (`queue.buffering.max.ms=0`), set it explicitly in producer config.
3. Encode the key in any custom `key_filter` so both sides are serialized bytes.

## Optional changes

- **`AvroLazyConsumer`** (`0.6`): public subclass that skips Avro decode in `poll`; call `decode_message` yourself. The loader uses it so it can filter on the raw key before decoding.
