# Migration Guide for v1

Migrating from `0.10` (`0.10.5`) to the latest `1.x` (`1.5.0`). 1.x releases are not tagged; versions are `setup.py` bumps on `master`.

## Required changes

- **OpenTracing is gone** (`1.0.0`): `extras_require['opentracing']`, `tracing.backends`, `tracing.tags`, and the null-tracer fallback are removed. Tracing always uses OpenTelemetry (`opentelemetry-api==1.27.0`).
- **`confluent-kafka[avro]==2.*`** (`1.0.2`): the `schema-registry` extra is dropped from this library's pin. Depend on `confluent-kafka[schema-registry]` yourself if you still need that extra.
- **`commit()` retries transient errors** (`1.2.0`): `REQUEST_TIMED_OUT` and `BROKER_NOT_AVAILABLE` are retried. No code change; commit can take longer under broker faults.
- **SIGTERM/SIGINT no longer exit immediately** (`1.3.0`): import sets a process-wide flag; `AvroConsumer` finishes the in-flight message and then leaves the loop. A second signal forces `sys.exit(0)`. Existing handlers are still invoked after the flag is set.

### Migration steps

1. Remove the OpenTracing extra and any imports of this library's OT API:

   ```text
   # Before (0.10)
   pip install confluent-kafka-helpers[opentracing]
   ```

   ```python
   # Before (0.10)
   from confluent_kafka_helpers.tracing import tags, tracer
   from confluent_kafka_helpers.tracing.backends.opentracer import OpenTracerBackend
   ```

   ```text
   # After (v1)
   pip install confluent-kafka-helpers
   ```

   ```python
   # After (v1) — only if you touch the tracer yourself
   from confluent_kafka_helpers.tracing import tracer
   from confluent_kafka_helpers.tracing import attributes as attrs
   ```

   Configure an OpenTelemetry `TracerProvider` in the app (or rely on your APM SDK). The library calls `trace.get_tracer`.

2. Treat SIGTERM/SIGINT as "stop after this message", not "exit now". Long handlers should poll the flag; raise Kubernetes `terminationGracePeriodSeconds` if a single message can exceed the default 30s:

   ```python
   from confluent_kafka_helpers import is_shutdown_requested

   for message in consumer:
       do_step_one(message)
       if is_shutdown_requested():
           break
       do_step_two(message)
   ```

   If another library's handler still calls `sys.exit`, import `confluent_kafka_helpers` *first* so its handler is the one installed, or accept that the other handler still exits immediately.

## Optional changes

- **Consumer action latency metric** (`1.5.0`): propagate `action_started_at` as epoch
  milliseconds to emit `confluent_kafka_helpers.consumer.action_latency` after the
  message handler returns. Metrics require `DATADOG_ENABLE_METRICS=1` and the optional
  `datadog` package.
- **Automatic header propagation** (`1.1.0`): set `headers.propagate` to a list of header keys on the consumer; the producer copies those values onto subsequent `produce` calls in the same context.
  The configured headers are also added to the related Kafka spans as
  `confluent_kafka_helpers.header.<header-name>` attributes.
  When `correlation_id` is configured for propagation, it is also recorded as
  the standard `messaging.message.conversation_id` attribute.

  ```python
  AvroConsumer({**config, 'headers.propagate': ['x-request-id']})
  ```

- **Producer OTEL service name** (`1.0.1`): produce spans set
  `confluent_kafka_helpers.producer.service.name` from `DD_SERVICE` / Datadog service name.
- **Consumer/producer use the package logger** (`1.1.2`): the underlying Confluent client is constructed with this library's structlog logger.
