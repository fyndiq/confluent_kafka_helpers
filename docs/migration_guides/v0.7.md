# Migration Guide for v0.7

Migrating from `0.6` (`v0.6.1`) to the latest `0.7.x` (`v0.7.10`).

## Required changes

- **PyPI name is `confluent-kafka-helpers`**: `pip install confluent_kafka_helpers` no longer matches the distribution. The import path is still `confluent_kafka_helpers`.
- **`confluent-kafka` 1.x**: pin moves from `==0.11.4` to `>=1.0.0,<=1.5.0` by `0.7.10`.
- **Default callbacks raise**: `error_cb` raises `KafkaError`; a failed `on_delivery` raises `KafkaDeliveryError`. Catch these or pass a callback that handles the error before the raise.
- **Datadog metrics are off unless `DATADOG_ENABLE_METRICS=1`**: previously any installed `datadog` was used.
- **Consumer `auto.offset.reset` default is `earliest` again** (0.5/0.6 used `latest`).
- **Producer defaults**: `enable.idempotence=True` and `linger.ms=1000`. Brokers must support idempotent producers; override if you cannot.

### Migration steps

1. Install the renamed package and a 1.x client:

   ```text
   pip install confluent-kafka-helpers==0.7.10
   ```

2. Handle delivery/error exceptions (or wrap your existing callbacks):

   ```python
   from confluent_kafka_helpers.exceptions import KafkaDeliveryError, KafkaError

   try:
       producer.produce(value, key=key)
   except KafkaDeliveryError as exc:
       handle(exc.error, exc.message)
   ```

3. Export `DATADOG_ENABLE_METRICS=1` if you still want statsd metrics from this library.

## Optional changes

- **`message._meta.headers`** (`0.7.5`): Kafka headers decoded to a `dict` (empty if missing).
- **Transport-error retries** (`0.7.1`): consumer/loader poll retries `KafkaError._TRANSPORT`.
- **Signal handlers chain existing ones** (`0.7.8`): `SIGTERM`/`SIGINT` call a handler that was already installed, instead of always `sys.exit`.
- **`fetch.min.bytes` / `fetch.wait.max.ms`** (`0.7.10`): consumer defaults `10000` / `1000`; loader `fetch.min.bytes` is `1000`.
