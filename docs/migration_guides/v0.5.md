# Migration Guide for v0.5

Migrating from `0.4` (`v0.4.3`) to the latest `0.5.x` (`v0.5.2`).

## Required changes

- **Consumer `auto.offset.reset` default is `latest`**: 0.3/0.4 defaulted to `earliest`. Set `'auto.offset.reset': 'earliest'` in `default.topic.config` if you still need to read from the beginning.
- **`fetch.message.max.bytes` default is `10500`**: large messages can fail or stall. Raise it (or wait for 0.6, which drops this default) if your payloads exceed ~10 KB.
- **Import replaces `SIGTERM`/`SIGINT` handlers**: the package installs handlers that `sys.exit` so `atexit` flush/close runs. Any handler you installed earlier is overwritten (0.7 starts chaining instead).
- **`fastavro[ujson]==0.16.7`** is a new direct dependency.

### Migration steps

1. Restore earliest reset if you depended on the 0.4 default:

   ```python
   config['default.topic.config'] = {
       **config.get('default.topic.config', {}),
       'auto.offset.reset': 'earliest',
   }
   ```

2. Raise `fetch.message.max.bytes` if messages can exceed 10 KB, on both the consumer and the loader consumer config.

## Optional changes

- **Datadog statsd metrics** (`0.5`): error/delivery/stats callbacks emit metrics when `datadog` is installed; pass your own `error_cb` / `stats_cb` / `on_delivery` and they are chained after the defaults.
- **Producer flush on exit** (`0.5`): `atexit` now flushes the producer.
- **Loader duplicate logging** (`0.5`): the message generator logs a critical when it sees the same payload more than once in one load.
- **`client.id`** defaults to the hostname; **`statistics.interval.ms`** defaults to 15000.
