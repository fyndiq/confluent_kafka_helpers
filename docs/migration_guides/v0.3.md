# Migration Guide for v0.3

Migrating from `0.2` (`v0.2`) to the latest `0.3.x` (`v0.3`).

## Required changes

- **`AvroConsumer` constructor**: pass a single `config` dict. Topics move into `config['topics']`; `timeout` is now `poll_timeout` inside that dict.
- **Consumer defaults**: `enable.auto.commit` is `False` and `auto.offset.reset` is `earliest`. Set them explicitly if you relied on librdkafka defaults.
- **`AvroProducer` config**: replace `default_topic` / `key_subject_name` / `value_subject_name` with `topics` (a list). Subject names are `{topic}-key` and `{topic}-value`. Key schema is optional.
- **`produce` signature**: `produce(value, key=None, topic=None, **kwargs)` — `value` is first; `key` is optional. Producing to a topic not in `topics` raises `TopicNotRegistered`.
- **No per-produce flush**: `produce` no longer calls `flush()`.
- **`SchemaNotFound`**: `get_latest_schema` raises if the subject is missing (previously returned `None`).

### Migration steps

1. Move consumer topics and timeout into config:

   ```python
   # Before (0.2)
   AvroConsumer(topic, config, timeout=0.1)

   # After (0.3)
   AvroConsumer({**config, 'topics': topic, 'poll_timeout': 0.1})
   ```

2. Switch the producer to a topic list and the new `produce` order:

   ```python
   # Before (0.2)
   AvroProducer({
       **config,
       'default_topic': 'orders',
       'key_subject_name': 'orders-key',
       'value_subject_name': 'orders-value',
   })
   producer.produce(key, value)

   # After (0.3)
   AvroProducer({**config, 'topics': ['orders']})
   producer.produce(value, key=key)
   ```

## Optional changes

- **Multi-topic produce** (`0.3`): register several topics and pass `topic=` to `produce`.
- **`value_serializer`**: constructor kwarg or config key (replaces `message_value_serializer`).
- **Consumer `__getattr__`**: unknown attributes proxy to the underlying Confluent consumer.
- **`confluent-kafka[avro]>=0.11.0`**: lower bound only; `requests` is no longer a direct dependency.
